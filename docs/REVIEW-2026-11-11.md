# Review, 11 November 2026 (Plus 0.7.0 → 0.8.0)

Every add-on, the installer scripts and the templates were read for bugs and for compatibility with the installed app (DeepSeek Harness 0.2.2-rc.1). Clear bugs and safe improvements were fixed in 0.8.0 (commit `d38839c`, local only). Anything that would change how a feature behaves is listed under **Your decisions** and was left as it was.

## Fixed in 0.8.0

**Stopping work**
- **Child agents now stop when cancelled.** The app's cancel signal only covers starting a child agent. A running child kept going (and spending) after you pressed stop or a swarm hit its budget. This affected swarm, deep research, code power's judge and the three Tier tools. It is fixed: the child is now shut down through its own handle. A new test proves it.
- **Benchmark:** an answer cut off by a timeout or cancel was scored as if it were complete. It is now recorded as an error. Spend is counted before grading, so a failed grading still adds to it. Closing the app marks running jobs "cancelled". Job ids are checked before a file is read. `/bench status` shows the newest job, including one still running. Only the 20 newest finished jobs stay in memory. The judge is no longer capped at 300 tokens, which cut off reasoning models.
- **Arena:** a cancelled round is dropped, not saved as a round of failures.

**Correctness**
- **Deep research** never recorded the URLs that searches returned, because it read the wrong field of the app's tool-result event. That is fixed. CSV cells that start with `=`, `+`, `-` or `@` are now stored as text, so a spreadsheet will not run them as formulas. Role names are now checked against plan, implement, review and fast.
- **Route health:** after a model came back, it switched a conversation back to that model, even if you had picked another model in the meantime. It now leaves your choice alone. A health check that finishes after shutdown no longer acts.
- **Opening a conversation could fail** if a prompt section of role prompts, context saver or swarm failed to install. Each one is now caught and logged. The sections are now removed when their add-on is switched off.
- **Context saver:** a helper that stops answering is restarted, not left hung.
- **Modes and Tiers:** saving no longer overwrites a change made at the same moment in another window. Old per-conversation entries are now cleaned up safely.
- **Usage ledger:** a damaged ledger file used to be overwritten with an empty one. It is now kept aside as `usage-ledger.json.damaged-<time>`.
- **Logging:** three log calls in notify and arena used a form the app does not support. They now use the same form as everything else.

**Security**
- **Media tools:** private addresses hidden in IPv6 forms are now blocked. Examples: `http://[::ffff:127.0.0.1]/`, NAT64, 6to4 and Teredo.
- **Colour schemes:** custom values must now be real colours as checked by the browser. `url(...)`, images, comments and escapes are refused. This was checked live.
- **Cowork shell:** the Connectors page shows only the address of a server, never secret-looking command arguments.

**Sync (the two-MacBook work)**
- **Encrypted sync could push only once after a pull.** The pull commit was not a descendant of the remote, so every later push was rejected. It now records a proper merge. A test runs two machines through pull → push → pull → push.
- **No re-encryption churn.** Every push used to re-encrypt and re-commit every session, so the sync repository grew by the whole store each time. Unchanged files are now skipped.
- **Open conversations** are left alone during a pull and arrive on the next pull, after you close them.
- **iCloud Drive paths work.** A remote can now be an absolute folder path containing spaces, for example `~/Library/Mobile Documents/...`.

**Installer**
- On failure, the installer now puts back the old add-on files first, then the setup that points at them. The order used to be reversed.
- Ctrl-C or closing the window part-way now undoes the install.
- Add-ons that a newer release no longer ships are unregistered. Otherwise the app would fail to load their missing folders. This was rehearsed in a throwaway folder.
- The uninstaller now only asks you to quit the app when there is something to remove. It also removes Plus add-ons left over from older releases.
- `check.sh` now handles folder paths with spaces.
- The backup template leaves out the installer's copies of your setup files, as it already did for the originals.
- **Docs:** the README version is updated, as are the sync notes. The providers template now explains why an API key set in `~/.zshrc` is not seen when the app is opened from the Dock.

**Checked:**
- All 5 test suites pass, 90 tests in total, including new ones for the swarm, sync and media fixes.
- `check.sh` passes: install, re-install, uninstall and the sidebar rule.
- In a throwaway lab, a conversation ran end to end. The Search toggle turned on and off. Colours refused a smuggled `url()`. The Tiers page loaded. There were no console or server errors.
- 0.8.0 is installed in your real app, which restarted and is running.

**Not checked:**
- Real `age` encryption, because it is not installed on this Mac. A stand-in was used.
- Sync over iCloud itself, because only local folders were used.
- Cancelling a real running child agent in the app. The unit tests use a fake one.

## Your decisions (left unchanged)

1. **Tier defaults are specific to your setup.** The shipped tier table names `omlx-max` and Qwen/Claude model ids. That breaks the "no user-specific defaults" rule for a version others install. Suggestion: ship empty tiers plus an example file, and keep yours in your own setup.
2. **Sampling presets, router and Tiers also act on sub-agents.** A child can get a different temperature or route than its parent asked for. Should they skip sub-agents?
3. **`setSessionTier` drops a tier's temperature and max tokens.** Only the route and effort are applied.
4. **Fallback on any error.** Tiers move to the next route on any model error, including a 400 for a bad request, not only on outages.
5. **Sampling-presets order.** When several presets match, the last one wins. Should the most specific one win instead?
6. **Router:** it acts on stream errors and polls in the background. Should it be quieter?
7. **Swarm and deep research return the full text twice.** With `delivery: 'parent'`, each child's answer is posted to the conversation and also returned to the model.
8. **The deep-research writer ignores `maxMinutes`.** The time limit stops searching, but writing can run past it.
9. **Modes:**
   - English defaults win over the Chinese locale.
   - The sandbox setting is not restored after a restart.
   - `/mode` on a brand-new conversation in the Cowork shell is overridden by the tab.
   - The Modes page saves `defaultMode` again when you open it.
   - Editing a mode changes the sandbox of conversations already using it.
10. **Sync:**
    - The device id is random per install, so reinstalling looks like a new machine.
    - The `engines` range is wider than what was tested.
    - Old backups are never pruned.

Tell me which of these you want, and I will change them.

## Two MacBooks, one synced setup (design note, not built)

You want the same Plus setup on both Macs, kept in step through a file, for example in iCloud Drive. A design that fits what is here:

- **One folder in iCloud Drive**, for example `iCloud Drive/DeepSeek Harness Plus/`, holding:
  - `settings.yml`: your Plus settings (tiers, modes, colour scheme, swarms, presets), with **no secrets**. Keys stay as names in each Mac's Keychain or environment.
  - `sessions.git`: a bare git repository used as the `dsh-sync` remote. Since 0.8.0 a path with spaces works, and encrypted pushes no longer churn, so iCloud has little to upload.
- **Installer option** `--settings <folder>` (and a "Use my iCloud settings" question in `Install.command`). It installs the add-ons, then applies `settings.yml` to the app's setup on that Mac. Running it on the second Mac gives the same setup.
- **Live sync of settings:** a small add-on watches `settings.yml` and applies changes on the fly. Writes go to a temporary file followed by a rename, so iCloud never sees half a file. A change made in Settings on one Mac is written back to the file.
- **Conversations:** `dsh-sync` with `remote: <that folder>/sessions.git`, the encrypted backend, and the same age key file on both Macs (copied by you, never synced). Push when you leave one Mac, pull on the other. Auto push and pull are already options.
- **Caveats:**
  - iCloud can lag or create "conflicted copy" files if both Macs write at once. A git repository survives that better than loose files, which is why sessions go through git.
  - Continuing the same conversation on both Macs at the same time ends in a fork file, by design.
  - A bare repository inside iCloud is not something Apple supports. If it ever misbehaves, a private GitHub repository works the same way.

Rough size: a day of work for the settings file, installer option and watcher add-on. Sync itself is already done.
