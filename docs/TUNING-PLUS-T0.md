# Tuning Plus, step T0: the plan checked against the code

17 November 2026, overnight. The plan is "Tuning Plus: plan for models that learn from your work" (the owner's file of 16 November). T0 builds nothing: it says what already exists, where Tuning Plus fits, and what differs from the plan. The owner was asleep and asked for the work to go on without stopping; every difference below was decided with the plan's recommendation and the safe default, and is listed at the end so he can agree or have it undone.

## Differences from the plan, decided for the owner

1. **Where it lives.** A new add-on, **Tuning Plus** (`dsh-tuning`): a Settings page with its bar (Model, Goal, Data sets, Method, Budget, Look only, the run in one sentence) and its result cards, and a few tools in the chat for plain-words requests. Not a tab of its own: the plan describes a bar and plain chat, not a mode.
2. **The trainer.** Apple's mlx-lm for supervised LoRA training. Preference pairs (the owner's edits) are kept and written out in the format preference trainers read; mlx-lm itself trains on the owner's version as the target. A preference trainer can be added when the owner installs one.
3. **Serving.** As in the table: a fused copy by default, mlx-lm's own server as the other choice; nothing starts by itself.
4. **The taste test.** The owner's recent real requests (from the logs) are answered again by the model in use and by the candidate, with the names hidden; he picks. Answering his *next* live requests twice would need a change in how the chat sends a turn, which is not additive.
5. **Lessons (T7).** Each plugin's lessons are built at run time from tool calls in the logs that succeeded, each checked against the tool's own parameter schema, and written to `<app data>/tuning/lessons/<plugin>/`, and also into Creator Plus's passport folder for that plugin when one exists (`<app data>/creator-plus/passports/<id>/lessons/`). Nothing is written into an installed add-on's own folder, because an install replaces it.
6. **Canaries.** A small built-in suite in Benchmark, graded by code (no judge model needed).
7. **The exam gate on rungs 1 to 3.** Only where an exam exists for that model and kind of work; otherwise Self-improve and Learned skills decide as today.
8. **Providers.** One "may train" switch per provider the app knows. All start at yes, except Anthropic's models for adapters that write open-ended text (the harness and voice adapters), which starts at off, as the plan says.
9. **The night shift.** Its own schedule on the Tuning Plus page (off until switched on), running only while the Mac is on power and has been idle; it stops a training run the moment the Mac is used. Offering it in the Automations tab is left for later (another add-on's page).

## Decided while building (each easy to undo)

10. **Which model takes the exam in Learned skills.** Its reading model (the one picked on Settings → Learned skills), without the skill and with it, because a skill has no model of its own. A skill that does worse is not added, but the card shows the result and an **Add anyway** button: the choice stays the owner's. Undo: remove `skillExam` from `dsh-skill-architect/index.js`.
11. **Self-improve's exam uses the whole playbook.** The owner's exam has no task families, so every lesson is tried, with the model version's own instructions in front.
12. **Rows never travel to a new provider.** A model that does not count as this Mac is examined (and asked in a taste test) only with rows and requests that were written to that same provider. Rows that never left this Mac stay on it. When too few rows qualify, the gate says nothing and the other add-on works as before.
13. **Helpers** are read under their conversation's rules: a helper of Recon is never read, whatever its own mode says. **Connectors** (tools named `mcp__…`) count as signed-in sources: rows from them never train.
14. **Code rows are marked by the shape of the tool call** (same tool, same argument names), not by running the tests again on the exam.
15. **Creator Plus builds** are read from `<app data>/creator-plus/builds/*.json` when Creator Plus writes them (a brief, files, and checks loads/tests/fit/trial all passed). Creator Plus now writes one masked record per finished build there (17 November, after the reviews).
16. **Lessons for Plus add-ons** go only to Tuning Plus's own folder (and to a third-party plugin's passport kept by Creator Plus), not into `passport/lessons/` inside an add-on's folder. Writing them there too is one line in `buildLessons` if the owner wants it.
17. **The settings page** is its own section (Settings → Tuning Plus), not grouped in Settings Plus's list (another add-on's file).
18. **A team member's adapter** is a shelf id typed on the member's row in Settings → Model Tiers; the member's own model stays as the fallback, and a member with only an adapter is not allowed.

## Decided after the independent review (each easy to undo)

19. **Only this Mac counts as this Mac.** A model at a home address (192.168…, .local) is treated like one on the internet unless the owner switches on **Count my own network's machines as this Mac** (off). A proxy on the owner's network that forwards to a cloud provider cannot be told apart. Undo: switch it on, or make `onThisMac` in `dsh-tuning/index.js` accept 'own network' again.
20. **A row's writer is whoever wrote its text**, never a label: the teacher model for questions, the model in use or the candidate (`mlx-local`) in a taste test, nobody known for research findings and Mission steps. A text whose writer nobody can say trains narrow tools only. Undo: `unknownWriter` in `lib/rows.js`.
21. **The newest turn waits six hours** (`QUIET_MS` in `lib/harvest.js`) unless a later turn exists; a turn let through and corrected later is taken out.
22. **Learned skills' exam runs in the background**: Accept answers at once; the skill is added when the exam is done and not worse.
23. **Limits**: 50,000 rows per file, 2 GB free to train, room for a copy of the base model to fuse, the newest ten candidates and 30 days for unpromoted entries.
